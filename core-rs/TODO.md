# 待办：让"别人好用"的代码层面改进

> 先记录、暂不改。这些是**接口/代码层面的顺手度**问题，不影响"能用"。
> 已完成的"能用"五坑见 git 历史（并发句柄防护、运行时复用、布局校验、容错加锁、暂停/恢复）。

1. **出参改结果结构体**
   现在是 `out_path / out_size / out_speed / out_parts / err` 一串参数，
   改成一个 `dc_result` 结构体，调用更清爽、以后加字段不破坏签名。

2. **错误码枚举**
   现在错误只有一个字符串；加分类错误码（可重试 / 致命 / 取消 / 磁盘满 / 文件变了……），
   宿主才能"按类型处理"，而不是解析文字。

3. **进度可查询**
   现在只能靠回调被动拿进度；加一个"随时查当前进度"的接口，方便宿主做界面。

4. **结果补元信息**
   结果里补上实际分段数、最终地址等，方便宿主展示与诊断。

5. **一个句柄下多个文件的接口形态**
   现在同一句柄一次只允许一个下载（已加防并发保护）；
   若宿主想"一个句柄管一批任务"，需要重新设计任务级接口。

6. **（功能扩展，另列）**
   代理、Cookie/凭据、校验和、镜像多来源、自适应并发。
